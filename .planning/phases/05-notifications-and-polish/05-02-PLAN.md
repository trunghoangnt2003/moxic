## Tasks

### 1. Add ActionRequired to OrderStatus Enum

- In `Moxic.Shared/Enums/MoxicEnums.cs`:
  - Add `ActionRequired` to `OrderStatus` enum (between Installing and Completed, or after Cancelled)
- Update any existing status transition logic to handle the new status

### 2. Create PaymentTimeoutService

- In `Moxic.Infrastructure/Services/PaymentTimeoutService.cs`:
  - Inherit `BackgroundService`
  - Configurable interval (default 15 min) from appsettings
  - Query: `Orders.Where(o => o.Status == OrderStatus.Pending && o.CreatedAt < DateTime.UtcNow.AddHours(-24))`
  - For each expired order:
    - Set Status = Cancelled
    - Set CancellationReason = "Hết hạn thanh toán sau 24 giờ"
    - Call IEmailService.SendOrderCancelledAsync()
  - Use IServiceScopeFactory for scoped DbContext + EmailService
  - Log count of auto-cancelled orders each run

### 3. Update Status Transition Rules

- In `AdminOrdersController.UpdateOrderStatus()`:
  - Add transitions for ActionRequired:
    - Verifying → ActionRequired (admin could not log in to Xbox)
    - ActionRequired → Verifying (customer updated info, retry)
    - ActionRequired → Cancelled (admin gives up)
  - Add Installing → Verifying rollback (install failure recovery)
  - When transitioning to ActionRequired, trigger email customer asking to update info
  - When transitioning from ActionRequired→Verifying, trigger email informing customer of retry

### 4. Register BackgroundService in Program.cs

- Add `builder.Services.AddHostedService<PaymentTimeoutService>()`
- Add optional config section for check interval

### 5. Build & Verify

- `dotnet build` passes
- Manual verification: set order CreatedAt to 25h ago, trigger service, verify auto-cancel + email
